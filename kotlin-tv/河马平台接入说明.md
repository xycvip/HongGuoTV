# 河马剧场平台接入说明

## 目标结构

红果与河马作为两个并列的平台上下文，顶部「切换平台」入口切换整套内容。两边复用现有 Android 页面组件和播放器外壳，但数据仓库、门户身份、本地记录和随机推荐池分别隔离。

## 河马 API 来源

协议实现以 `Gavinme/hmjc-flutter` 当前 `main` 分支为依据，关键文件：

- `lib/core/portal_api.dart`：门户请求、设备初始化、协议请求头、双域名和双传输回退。
- `lib/core/portal_crypto.dart`：AES-CBC / PKCS7 加解密。
- `lib/data/content_repository.dart`：首页、剧场、搜索、详情、播放解析 API。
- `lib/data/models.dart`：短剧、剧集和播放地址字段映射。

## 当前接入映射

| 功能 | 河马接口 | Android 适配 |
|---|---:|---|
| 设备注册 | 1103 | HippoPortalApi.ensureInitialized |
| 首页推荐 | 1113 | HippoContentRepository.home |
| 剧场栏目/分类 | 1125，兼容回退 1121 | HippoContentRepository.theater |
| 搜索热词/榜单数据 | 1801 | suggest / ranking |
| 搜索结果 | 1803 | search |
| 剧集详情/目录 | 1132 | detail |
| 单集播放地址 | 1133 | stream |

请求采用两个门户域名顺序尝试，每个域名依次尝试普通 JSON 和 AES 加密传输。设备标识、临时标识、安装时间、userId 和请求会话均保存在 `hippo-portal-v1`，不读取红果 Native/Phoenix 的注册状态。

## 本地隔离

- 红果沿用既有 `native-library-v1` 和 `native-home-cache-v1`，升级不迁移、不清空。
- 河马使用 `hippo-native-library-v1` 和 `hippo-native-home-cache-v1`。
- 河马门户身份使用 `hippo-portal-v1`。
- 河马随机推荐池使用 `hippo_random_pool`。
- 平台选择持久化在 `content-platform-v1`。
- 搜索历史、收藏、观看历史、首页缓存及 Library 内的播放偏好按平台存储。

## 播放隔离

河马单集 ID 在详情层编码为 bookId/chapterId 组合，播放时只调用河马 1133。河马播放不会回退到红果 Native 或 Phoenix；播放缓存键也包含平台 ID。

红果官方评论和红果弹幕接口不用于河马播放。当前河马平台不提供对应的红果评论/弹幕功能，因此在河马播放时隐藏评论入口并阻止红果弹幕请求。

## 仍需验证的边界

- 必须通过 Android Debug 构建与单元测试。
- 必须在真实 Android 设备上验证 1103、1113、1125、1801、1803、1132、1133 的完整请求链。
- 必须验证河马播放 URL 在设备端可解码、清晰度与备用 URL 处理，以及播放头/Range 兼容性。
- Flutter 项目还有剧单 1115/1116 等独立能力；若需要在原生 UI 暴露剧单页，应另行增加明确页面入口，不能把它伪装成已经完成。
- 收藏/历史数据隔离已使用独立 Library 空间，但需要真机验证切换前后记录、重启恢复和备份行为。

## 安全与兼容

- Android 最低版本保持现有 minSdk 26（Android 8.0），不提高系统要求。
- 网络请求使用 OkHttp，同步调用由现有 IO worker 调度，不在主线程执行。
- 不采集真实 IMEI/OAID；门户请求字段按来源客户端使用空值。
- 日志只记录接口阶段、异常类型和简要错误，不记录完整播放 URL、Token 或加密请求体。
